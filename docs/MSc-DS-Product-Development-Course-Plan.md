## 1. Preamble

The School of Digital Sciences proposes a two-year postgraduate programme, **M.Sc. Data Science and Product Development**, delivered under a structured **Work Integrated Learning Model (WILP)**.

The programme is aligned with:

- UGC Regulations for Postgraduate Programmes
- UGC Credit Framework
- NEP 2020 Experiential and Skill-Integrated Learning Framework
- Outcome-Based Education (OBE) Model

It integrates **Artificial Intelligence, Data Systems, and Full-Stack Engineering** to produce industry-ready **AI Product/Solution Engineers**.

---

## 2. Program Objectives

The programme aims to:

- Develop AI-driven digital product/solution engineers
- Integrate full-stack and cloud-native development skills
- Embed DevOps and MLOps pipelines in production systems
- Promote agile product development methodologies
- Ensure governance, industry standards, and security compliance

## 3. Program Highlights

- **2 Years | 4 Semesters | 80 Credits**

## 7. Programme Structure (Semester-wise)

Each semester carries **20 credits**.

### Semester I — Foundation & Ideation (20 Credits)

| Component | Detail | Credits |
|-----------|--------|---------|
| Core | CS101: Advanced AI & Machine Learning (3-0-1) | 4 |
| Core | CS102: Full Stack Architecture & Cloud-Native Dev (1-0-3) | 4 |
| Electives | 3 subjects × 3 credits | 9 |
| Project Lab I | Market research, tech-stack selection, UI/UX prototyping | 3 |

**Outcome:** Validated project idea, architecture blueprint, and high-fidelity UI prototype.

### Semester II — Backend & AI / Full-Stack Engineering (20 Credits)

| Component | Detail | Credits |
|-----------|--------|---------|
| Core | CS103: Modern Backend Systems & Data Engineering | 4 |
| Core | CS105: DevOps & Automated Pipelines | 4 |
| Electives | 3 subjects × 3 credits | 9 |
| Project Lab (Mini Project II) | AI model + backend CRUD operations | 3 |

**Outcome:** A functional backend with a trained AI model (or full-stack solution) accessible via a local environment.

### Semester III — Integration & Cloud Orchestration (20 Credits)

| Component | Detail | Credits |
|-----------|--------|---------|
| Core | CS104: API Design & Microservices Orchestration | 4 |
| Electives | 4 subjects × 3 credits | 12 |
| Project Lab (Mini Project III) | Integrate middle layer, connect third-party APIs (payment gateways, external data), deploy to cloud | 4 |

**Outcome:** A fully integrated, "live" digital product — the capstone transitions from a local backend to a live, microservices-based product.

### Semester IV — Final Project, Solution Demonstration, Report & Viva (20 Credits)

- **Duration:** 6 months
- **Final Project Development** within DUK CDIPD Lab — 12 credits
- **Report and Viva** — 8 credits
- **Mandatory:** Students must be placed in a role involving AI or Full-Stack development.
- **Assessment:** Monthly progress reports, industry mentor evaluation, final solution/product evaluation, and a final viva voce.

## 8. Detailed Syllabus — Core Courses

> Format for all core courses: **L–T–P: 2–0–2 | Credits: 4**. Each unit pairs a hands-on activity with concrete tasks.

### CS101: Advanced AI & Machine Learning

**Unit 1 — Data Engineering & Feature Orchestration**
*Activity: Building an automated data pipeline.*
- **Data Review:** Use visual tools (Seaborn, Plotly) to find errors or bias in data.
- **Automated Cleaning:** Write scripts to fix missing values and scale numbers.
- **Vectorization:** Turn text/images into numbers using Word2Vec or BERT.

**Unit 2 — Neural Architecture & Deep Learning Sprints**
*Activity: The Architecture Shootout.*
- **Simple Models:** Use Random Forest for a baseline score.
- **Deep Learning:** Build custom networks for images/text using PyTorch or TensorFlow.
- **Transfer Learning:** Adapt a pre-trained model to a specific task.

**Unit 3 — Hyperparameter Optimization & Model Explainability**
*Activity: Systematic tuning and testing.*
- **Auto-Tuning:** Use Optuna to find the best settings for speed and accuracy.
- **Error Check:** Locate exactly where the model makes mistakes.
- **AI Explanation:** Use SHAP or LIME to see which data points matter most.

**Unit 4 — AI Model Deployment & Inference via API**
*Activity: Creating the AI-as-a-Service.*
- **Packaging:** Put the model inside a Docker container.
- **API Setup:** Use FastAPI so other programs can call the model.
- **Speed Optimization:** Shrink the model to run faster.
- **Monitoring:** Track the model to ensure it stays accurate over time.

**Assessment:** 70% Project | 30% Theory

### CS102: Full Stack Architecture & Cloud-Native Development

**Unit 1 — Multi-Tier Ecosystem**
*Activity: Architecting the project structure.*
- **Tech Stack:** Choose the front-end and back-end tools.
- **Data Plan:** Design how to store user info and AI results.
- **System Map:** Diagram how data moves from screen to AI and back.

**Unit 2 — The Middle Layer & API Orchestration**
*Activity: Building a Unified API Gateway.*
- **Server Build:** Use Node.js or FastAPI for the main logic.
- **External Data:** Connect to outside services (weather, finance feeds).
- **Speed:** Use Redis to cache common data.

**Unit 3 — Containerization & Microservice Orchestration**
*Activity: Dockerizing the system.*
- **Dockerfiles:** Write setup files for every part of the app.
- **Local Setup:** Use Docker Compose to run everything together.
- **Scaling:** Use Kubernetes to handle many concurrent users.

**Unit 4 — Cloud-Native Deployment & Serverless Logic**
*Activity: The Zero-Downtime Cloud Launch.*
- **Cloud Setup:** Use Terraform to provision servers and databases.
- **Serverless:** Use AWS Lambda for small tasks to save cost.
- **Security:** Use secure logins and protect private API keys.

**Assessment:** Deployment + Architecture Review

### CS103: Modern Backend Systems & Data Engineering

**Unit 1 — Advanced Database Design**
*Activity: The Hybrid Data Schema Build.*
- **Standard Databases:** PostgreSQL for user accounts and billing.
- **Flexible Databases:** MongoDB for logs and irregular data.
- **AI Databases:** Pinecone to store and search AI vectors.

**Unit 2 — Real-time Data Engineering & Event Streaming**
*Activity: Building a data pipeline.*
- **Messaging:** Use Kafka or RabbitMQ to send data between services.
- **Live Processing:** Update the user's screen instantly as the AI works.
- **Syncing:** Keep the main database and search tools perfectly matched.

**Unit 3 — Asynchronous Task Processing**
*Activity: Manage Latency.*
- **Background Jobs:** Use Celery to handle slow AI tasks without freezing the app.
- **Caching:** Use Redis to store frequent answers.
- **Efficiency:** Manage many tasks at once without errors.

**Unit 4 — Data Orchestration & ETL/ELT for AI**
*Activity: The Automated Data Pipeline.*
- **Scheduling:** Use Airflow to schedule data moves.
- **Combining Data:** Pull and clean data from three different sources.
- **Tracking:** Build a system that records how well the AI is doing.

### CS104: API Design & Microservices

**Unit 1 — API Design & Documentation**
*Activity: The API Contract Sprint.*
- **Blueprints:** Use Swagger to design the API before coding.
- **Best Practices:** Follow standard REST conventions for requests and errors.
- **Smart Queries:** Use GraphQL so the front end fetches only what it needs.

**Unit 2 — Microservices Decomposition**
*Activity: The Service Split.*
- **Fast Talk:** Use gRPC for high-speed internal communication.
- **Independent Services:** Ensure parts can fail without breaking the whole.
- **Service Registry:** Help services discover each other automatically.

**Unit 3 — The API Gateway**
*Activity: Implementing a Traffic Controller.*
- **Gateway Setup:** Use Kong or AWS to manage incoming traffic.
- **Data Aggregation:** Combine data from AI and database into one package.
- **Security:** Use tokens to block unauthorized users.

**Unit 4 — Service Mesh & Resilience**
*Activity: The Chaos Engineering Test.*
- **Traffic Management:** Use Istio to control service-to-service communication.
- **Safety Switches:** Use circuit breakers to stop a slow service from crashing the app.
- **Tracing:** Use Jaeger to follow a request through the system.

### CS105: DevOps & Automated Pipelines

**Unit 1 — The CI/CD Engine**
*Activity: Building the Green-to-Green Pipeline.*
- **Auto-Flow:** Use GitHub Actions to trigger builds on commit.
- **Quality Checks:** Automatically reject code that fails tests.
- **Image Storage:** Save Docker images to a private registry.

**Unit 2 — Infrastructure as Code & GitOps**
*Activity: The Scripted Data Center.*
- **Code-Based Servers:** Use Terraform to define cloud hardware.
- **Software Setup:** Use Ansible to install software inside containers.
- **Auto-Sync:** Use ArgoCD to keep the live app matched with the code.

**Unit 3 — MLOps**
*Activity: Building DVC and automatic retraining.*
- **Data Versioning:** Track dataset changes just like code.
- **Auto-Retrain:** Retrain the model when new data arrives.
- **AI Serving:** Deploy the model to handle many concurrent requests.

**Unit 4 — Observability & Feedback**
*Activity: Monitor and update.*
- **Log Gathering:** Use the ELK stack to collect error reports.
- **Dashboards:** Build Grafana dashboards to watch system health.
- **Alerts:** Get notified if the AI misbehaves or the app crashes.

## 9. Detailed Syllabus — Electives

> All electives follow **L–T–P: 2–0–2 or 3–0–0 | Credits: 3**, and each includes a unit-based theoretical framework, a hands-on activity, a real-world implementation task, and integration into the capstone product.

### Category A — Artificial Intelligence Focus

#### CS201: Natural Language Processing (NLP)

**Unit 1 — The Vector Space** *(Activity: Semantic Map Visualizer)*
- **Word Prep:** Tokenize and clean text.
- **Context:** Compare how words change meaning across sentences.
- **Vector Search:** Store text as vectors for fast searching.

**Unit 2 — The Transformer Core** *(Activity: Mini-GPT from scratch)*
- **Attention:** Build a mechanism to focus on important words.
- **Logic Types:** Compare BERT (understanding) vs GPT (generation).
- **Word Order:** Teach the model sequence via positional encoding.

**Unit 3 — LLMs & Fine-Tuning** *(Activity: Private Knowledge Assistant)*
- **Light Training:** Use LoRA to train large models on modest hardware.
- **Adding Knowledge:** Connect an LLM to a PDF (RAG) to answer questions.
- **Prompting:** Use LangChain to automate instruction pipelines.

**Unit 4 — Agentic NLP & Production** *(Activity: Autonomous Researcher Agent)*
- **Tool Use:** Teach the model to use search or a database.
- **Shrinking:** Compress large models to run on a phone.
- **Judging:** Use one model to grade another (LLM-as-judge).

#### CS202: Computer Vision (CV)

**Unit 1 — Digital Sight** *(Activity: Photo Enhancer)*
- **Edge Detection:** Use filters to find object outlines.
- **Colors:** Isolate objects by color/brightness.
- **Cleaning:** Use masks to remove noise.

**Unit 2 — Spatial Features (CNNs)** *(Activity: Medical X-Ray Classifier)*
- **Layers:** Learn how CNNs perceive textures and shapes.
- **Compression:** Pool image data to focus on major features.
- **Variety:** Augment images (rotate, blur) to improve learning.

**Unit 3 — Object Detection** *(Activity: Real-time Traffic Monitor)*
- **Boxes:** Teach the model to draw bounding boxes.
- **Speed:** Use YOLO for live-video detection.
- **Small vs Large:** Detect objects across scales.

**Unit 4 — Advanced Vision** *(Activity: Hand Gesture Controller)*
- **Vision Transformers:** Apply attention to images.
- **Outlining:** Use segmentation to mask exact object regions.
- **Mobile Use:** Convert models to run on mobile devices.

#### CS301: Reinforcement Learning (RL)

**Unit 1 — The Agent-Environment Loop** *(Activity: Gridworld Optimizer)*
- **Setting the Stage:** Define states, actions, and transition probabilities.
- **Rewards:** Design a reward system that encourages fast wins.
- **Math Logic:** Compute optimal long-term moves via the Bellman equation.

**Unit 2 — Q-Learning & Deep Networks** *(Activity: Atari Champion)*
- **Memory:** Build a replay buffer to learn from past experience.
- **Stability:** Use a target network to steady learning.
- **Testing:** Balance exploration with exploitation.

**Unit 3 — Policy Gradients & PPO** *(Activity: Bipedal Walker)*
- **Step Control:** Use PPO to keep updates small and safe.
- **The Team:** Use an Actor to act and a Critic to evaluate.
- **Advantage:** Estimate how much better a move was than average.

**Unit 4 — Sim-to-Real & Deployment** *(Activity: Robust Robot Arm)*
- **Variety Training:** Vary physics (e.g., gravity) for robustness.
- **Multi-Agent:** Coordinate multiple agents.
- **Exporting:** Transfer the policy from simulation to a real machine.

#### CS401: Generative AI & Prompt Engineering

**Unit 1 — Latent Space & Diffusion** *(Activity: Custom Image Generator)*
- **Compression:** Map images into latent space and back.
- **Denoising:** Turn noise into a clear picture.
- **Text Guidance:** Use CLIP to match images to prompts.

**Unit 2 — Advanced Prompting** *(Activity: Logic Puzzle Solver)*
- **Reasoning:** Make the model explain its work step by step.
- **Examples:** Provide few-shot samples.
- **Safety:** Prevent prompt-injection attacks.

**Unit 3 — Synthetic Data & Fine-Tuning** *(Activity: Data Factory)*
- **Following Orders:** Instruction-tune a model.
- **Human Feedback:** Use RLHF to make outputs more helpful.
- **Small Models:** Distill a large model into a smaller, faster one.

**Unit 4 — Multi-Modal GenAI & Agents** *(Activity: Multi-Modal Assistant)*
- **Vision-Text:** Have the model describe images.
- **Logic Loops:** Build a self-checking agent.
- **Action:** Let the agent click buttons or send emails.

#### CS501: AI Ethics & Governance

**Unit 1 — Quantifying Bias** *(Activity: Fairness Auditor)*
- **Group Math:** Check for equal treatment across groups.
- **Error Balance:** Ensure errors aren't concentrated in one group.
- **Fixing Bias:** Adjust data or model to improve fairness.

**Unit 2 — Explainability (XAI)** *(Activity: Model Interpreter)*
- **Feature Check:** Identify which features drove a decision.
- **Visual Maps:** Highlight image regions the model focused on.
- **Logic Tracking:** Trace which words influenced an answer.

**Unit 3 — Security & Adversarial AI** *(Activity: Red Team Exercise)*
- **Tricking the AI:** Craft adversarial noise to fool the model.
- **Poisoning:** Identify data that could corrupt training.
- **Privacy:** Filter personal information from inputs.

**Unit 4 — Compliance & Rules** *(Activity: Compliance Dashboard)*
- **Risk Levels:** Classify AI apps by legal risk.
- **Model Cards:** Document how a model was built and its limits.
- **Human Overrides:** Provide a kill switch for human control.

### Category B — Full Stack & Engineering Focus

#### CS601: Advanced Frontend Frameworks

**Unit 1 — Rendering Strategies** *(Activity: Zero-Lag News Portal)*
- **Fast Loading:** Use Server-Side Rendering for instant pages.
- **Background Updates:** Refresh content without blocking the user.
- **Fixing Jumps:** Prevent layout shift during load.

**Unit 2 — State & Data Flow** *(Activity: FinTech Onboarding Engine)*

**Unit 1 — System Foundations** *(Activity: Global Consensus Engine)*
- **Trade-offs:** Balance speed against consistency.

**Unit 2 — Blockchain Logic** *(Activity: Secure Smart Contract)*
- **Smart Contracts:** Write on-chain code.
- **Cost Cutting:** Optimize for lower gas costs.

**Unit 1 — Mental Models** *(Activity: Minimalist Dashboard Redesign)*
- **Brain Rules:** Place controls where the hand and eye naturally go.
- **Simplicity:** Reduce choices to speed decisions.
- **Organization:** Group items to match user expectations.

**Unit 2 — User Research** *(Activity: A/B Test Experiment)*
- **Testing:** Observe users to find friction.
- **Heatmaps:** See where users click.
- **User Profiles:** Build personas.

**Unit 3 — Accessibility** *(Activity: Screen-Reader Optimized Storefront)*
- **Colors:** Ensure readable contrast.
- **Keyboards:** Support mouse-free navigation.

**Unit 4 — Micro-interactions** *(Activity: Haptic Feedback System)*

**Unit 3 — Interaction** *(Activity: Gaze-and-Gesture Controller)*
- **Hands:** Track hands without a controller.

The 25 figure makes the grand total reconcile to 80, but conflicts with the earlier "Core = 20" line.
